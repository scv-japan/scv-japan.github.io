1997 年 12 月 19 日 - 22 日 に Shonan Village Center で開催された研究
集会 Hayama Symposium on Sevral Complex Variables への参加申込をホー
ムページ上で行うことができるようにしましたが, その仕様は次の通りです.

  申込文書は, ブラウザに表示されるとともに, 本人にメールが届きます.
受け取り側では tahensu の下の pub/log/wsscv.log.data に申込文書を追加
するとともに tahensu@mis.hiroshima-u.ac.jp 宛にメールが届きます. 更に
受け取った form そのままをpub/log/wsscv.log.form に保存します.
  実際には次の順で作業が行われます. 2 以降は wsscvreg.pl によって処理
されます.

  1. 申込者が書き込みをした後, 送信ボタンを押す.
  2. 送信された form を受け取る.
  3. form を解析し必要な処理を行う. すなわち, データの分割, 漢字コー
    ドの EUC への統一, 改行コードの space への変更など.
  4. 受け取った form をそのまま pub/log/wsscv.log.form に append す
    る.
  5. 申込書, すなわち, 処理されたデータを pub/log/wsscv.log.data に
     append する. これは EUC コード.
  6. 申込書を tahensu@mis.hiroshima-u.ac.jp 宛に送信する. この際, EUC
     コードを JIS コードに変換する.
  7. 申込書をブラウザの画面に表示する. これは EUC コード.
  8. 申込書を申込者に送信する. この際, EUC コードを JIS コードに変換
     する.

  上記の 4, 5, 6 の段階でエラーが生じた場合, たいていは書き込み失敗の
場合ですが, この場合は終了します. 申込者の側では, "文書にデータが含ま
れていません" という(意味不明の)メッセージを見ることになります. そこ
で, 申込期間に入るまでは, pub/log/wsscv.log.form を書込み禁止にするこ
とによって, 申込を禁止することができます. なお, 現在, 以下の問題点が 
あります.

  1. メールの送信者が tahensu ではなく Nobody であること. したがって,
     申込者の e-mail address が間違っていた場合, tahensu ではなく,
     広島大学の postmaster (= server の管理者) のところに返送されてし
     まうこと. ただし, From と Reply-to: は Nobody から tahensu@...  
     に変えているので, 少なくとも Nobody 宛に返信メールを書かれてしま
     うことはありません. ただし, 申込書は確実に tahensu 宛に届くので,
     申込んだこと自体は無効にはならない.
   
  2. 上記に関連するが e-mail address の間違いで予想されるものとして
     全角英数字で書いてしまって気がつかないことが起こり得ること.
     全角を半角に変換する subroutine を作ればよいのだが, これも多少問
     題があると思われる.

  3. 漢字コードの変換には free の jcode.pl を使っているが, これも変換
     を間違えることもあるかもしれないこと. そういう理由もあって, ロー
     マ字氏名は必ず書いてもらうことにした. もちろん変換がうまく行くこ
     とが普通なので, e-mail address と違ってローマ字氏名が全角で書い
     てあっても問題は少ない.

  4. 入力情報のチェックは home page (= wsscv01.htm) 上で Java Script
     により行っているが, これはローマ字氏名と e-mail address を書いて
     いるかどうかのチェックだけである. もちろん, もう少し詳しくはでき
     るが, 全角/半角の判別などは現在の Version の Java Script では無
     理みたいである. Version の低いブラウザでは Java Script が利用で
     きなかったりするので, このことも問題である.
